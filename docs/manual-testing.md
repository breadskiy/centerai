# Как самому проверить CenterAI

Начни с раздела 1. После него у тебя будет рабочий сценарий с известным результатом. На его копиях удобно проверять остальные функции. Для основной проверки достаточно браузера.

## 1. Первый запуск с известным ответом

1. Открой [CenterAI](http://127.0.0.1:8000). Если страница недоступна, в Проводнике открой папку `D:\Cybergarden` и дважды щёлкни **Start-CenterAI.cmd**. Дождись открытия браузера. Окно запуска оставь открытым.
2. Слева нажми **Проекты → Новый проект**. В поле **Название** введи `Repair Desk — ручной тест`. Описание можно оставить пустым.
3. Для воспроизводимого результата скачай [ZIP проверенной версии Repair Desk](https://github.com/TBagirov/training/archive/fe1fcbe212669783480666b9b60147c8a8c6eef4.zip). Выбери **ZIP → Выберите ZIP с проектом**, укажи скачанный файл и нажми **Создать проект**. Распаковывать его не нужно. Откроется карточка проекта.
4. Чтобы отдельно проверить импорт по ссылке, создай второй проект с другим названием. Выбери **GitHub**, оставь предложенную ссылку на `TBagirov/training` и нажми **Создать проект**. Этот способ берёт текущую версию репозитория. Дальше работай с первым проектом из ZIP.
5. В карточке первого проекта нажми **Создать сценарий**. Назови его `Базовая проверка`. В поле **Начальный граф** выбери **Три анализатора и отчёт**, затем **Открыть редактор**.
6. На полотне должны быть **6 узлов и 7 связей**. Ручной запуск ведёт к исходникам, оттуда идут три ветви к Secrets, SCA и SAST. Все три сходятся в отчёт.
7. Нажми **Проверить**. Ожидаемое сообщение — **Граф прошёл проверку**. Затем нажми **Запустить**. Откроется монитор. Дождись статуса **Завершён**.
8. Нажми **Открыть находки** именно в этом запуске. На проверенном ZIP ожидаются **15 находок**: 5 SECRET, 5 SCA и 5 SAST. По критичности — 1 CRITICAL, 7 HIGH, 6 MEDIUM и 1 LOW. Обзор рабочего пространства суммирует результаты разных запусков, поэтому там число может быть больше.

## 2. Посмотреть доказательство и проверить экспорт

| Что нажать | Что проверить |
| --- | --- |
| **Открыть находки → Все анализаторы → SECRET** | Видно 5 строк. Нажми название или стрелку справа. В карточке есть путь, строка, факт анализатора и исправление. Значение секрета скрыто. |
| **Все анализаторы → SCA**, затем введи `jsoup` в поле **Путь, класс или advisory** | Останется зависимость jsoup. В подробностях видны её версия, идентификатор advisory и рекомендация. |
| Очисти поиск, верни **Все анализаторы**, выбери **Все уровни → CRITICAL** | Для этого запуска останется одна находка. **По пути** и **По критичности** меняют порядок. **Группировать** разделяет строки по анализаторам. |
| **Открыть запуск** в карточке находки или **Запуски → название сценария** | Монитор показывает граф именно выполненной версии, время и журнал событий. Раскрой **Данные этапов** и нажми идентификатор узла, чтобы увидеть его выход. |
| **Порядок исправлений → название находки** | Откроются подробности приоритетной проблемы. Объяснения в этой версии формируют правила анализаторов. Модуль нейросети отложен. |
| **JSON**, затем **TXT** в блоке результата | Перед кнопками должна быть надпись **Структура JSON проверена**. Открой оба файла из загрузок браузера. В JSON есть массив `findings` с 15 элементами, в TXT — те же результаты с текстовыми рекомендациями. [Образец JSON](example/submission.json) · [Образец TXT](example/report.txt) |

## 3. Карта экранов и кнопок

| Экран | Что делают элементы управления |
| --- | --- |
| **Обзор** | **Добавить проект** появляется в пустом пространстве, **Создать сценарий** — после добавления проекта. **Запустить проверку** позволяет выбрать существующий сценарий. Счётчики ведут в соответствующие разделы, **История** — к запускам, уровень в блоке критичности — к отфильтрованным находкам. |
| **Проекты** | **Новый проект** импортирует ZIP или GitHub. Поиск и **Все источники** фильтруют список. Нажатие на строку открывает проект. **Изменить** меняет название и описание. **Сценарии проекта** показывает связанные графы. **Удалить** архивирует проект и его сценарии после подтверждения, история проверок сохраняется. |
| **Сценарии** | **Новый сценарий** предлагает готовый граф или **Только триггер**. Название открывает редактор. Значок двух листов **Скопировать** создаёт независимую копию, корзина удаляет сценарий после подтверждения, **Запуск** сразу запускает сохранённый граф. Выпадающий список фильтрует по проекту. |
| **Запуски** | Выбери проект и статус. Название сценария или стрелка открывают один запуск. **Назад / Далее** переключают страницы длинной истории. **Отменить запуск** доступна в очереди или во время выполнения. Уже начатый этап может успеть закончиться. На небольшом проекте весь запуск иногда завершается раньше, чем появится возможность нажать кнопку. |
| **Находки** | Боковое меню открывает результаты всего пространства. Переход из монитора ограничивает список одним запуском. Фильтры, поиск, группировка и кнопки подробностей описаны в разделе 2. |
| **Настройки** | Здесь сохраняются параметры Telegram, проверяется доставка, меняется расписание и отображается список разрешённых GitHub-репозиториев. Для собственного учебного проекта проще использовать ZIP. |

## 4. Как пользоваться редактором

Для экспериментов открой **Сценарии → Скопировать** у базовой проверки. Наведи указатель на кнопку без подписи, чтобы увидеть подсказку.

- **Добавить узел.** Нажми **Узлы**, найди тип через **Найти узел**, затем нажми его название или перетащи на полотно. Заголовки групп сворачивают и раскрывают палитру.
- **Соединить.** Перетащи линию от правого кружка первого узла к левому кружку второго. Есть и более точный способ: выбери **принимающий** узел, открой **Входящие связи**, в **Вход из узла** укажи предшественника и нажми **Соединить**. Для IF / ELSE дополнительно выбери **Ветвь → Да** или **Нет**.
- **Убрать связь.** В том же списке нажми корзину рядом с нужным предшественником. **Удалить узел** убирает выбранный узел вместе с его связями. Крестик **Свернуть инспектор** только закрывает панель.
- **Перемещаться.** Перетащи карточку за её тело. Перетаскивание фона двигает полотно, колесо мыши и кнопки **+ / −** меняют масштаб. **Весь граф** возвращает все узлы в поле зрения. Замок на панели полотна переключает доступность взаимодействия.
- **Сохранить.** Вверху можно изменить название. Шестерёнка **Настройки сценария** открывает описание. Дискета **Сохранить** сохраняет текущие изменения. При автосохранении дождись надписи **Сохранено**.
- **Проверить и выполнить.** **Проверить** проверяет связи и параметры. **Запустить** выполняет граф над файлами проекта. Для проверки ошибки добавь **Regex** и оставь его вход свободным: появится сообщение о неподключённом узле, запуск будет недоступен. Удали этот узел и проверь граф снова.
- **Вернуться к версии.** Измени название и сохрани. Нажми значок часов **Версии**, найди прежнее название, нажми **Загрузить** и дождись сохранения. Открой старый запуск: в его истории останется версия, с которой он выполнялся.

## 5. Проверить каждый тип узла своими руками

Базовый запуск уже проверил **Ручной запуск**, **Исходники**, **Secrets** (учётные данные), **SCA** (зависимости Gradle), **SAST** (код и настройки Kotlin) и **Отчёт**. Для каждого эксперимента ниже удобнее создавать новый сценарий на том же ZIP, выбрав **Только триггер**. Узлы добавляй и соединяй по инструкции выше.

| Эксперимент | Что собрать и выставить | Ожидаемый результат |
| --- | --- | --- |
| Фильтр критичности | **Ручной запуск → Исходники → SCA → Критичность → Отчёт**. У узла **Критичность** оставь галочку только у CRITICAL. | На выходе SCA — 5, в отчёте — 1. Сравни через **Данные этапов**. |
| Фильтр по пути | **Ручной запуск → Исходники → Secrets → Regex → Отчёт**. В поле **Выражение для пути** введи `application[.]yml$`. | Из пяти находок Secrets в отчёт проходит одна, в файле `src/main/resources/application.yml`. |
| Обе ветви IF / ELSE | **Ручной запуск → Исходники → Secrets → IF / ELSE**. Добавь два отдельных узла **Отчёт**. Один подключи к выходу **Да**, другой — к **Нет**. У условия выбери оператор `>` и порог `0`. Запусти. Затем поставь порог `5` и запусти снова. | В первом запуске условие `5 > 0` истинно, отчёт на ветви **Нет** пропущен. Во втором `5 > 5` ложно, пропущена ветвь **Да**. Число находок в обоих отчётах одинаковое. Разницу смотри в **журнале и статусах узлов**. |

Если встраиваешь фильтр в готовый граф, удали прямую связь между анализатором и отчётом, которую он заменяет. Иначе часть данных дойдёт до отчёта в обход фильтра.

## 6. Проверить автоматический запуск

1. Скопируй базовый сценарий, пока у него ручной триггер. Назови копию `Тест расписания`.
2. Удали **Ручной запуск**. Добавь **Расписание** и соедини его с **Исходники**. В графе должен быть один триггер.
3. У узла укажи **Cron** `* * * * *` и **Часовой пояс** `Europe/Moscow`. Включи **Включить расписание**, сохрани граф.
4. Открой **Настройки → Расписание**, выбери свою копию и проверь **Следующий запуск**. Оставь сервер включённым. После ближайшей смены минуты открой или обнови **Запуски**. Должна появиться новая запись без ручного нажатия **Запустить**.
5. В **Настройки → Расписание** сними **Включено** и нажми **Сохранить расписание**. В поле следующего запуска появится прочерк. Уже созданная запись останется в истории.

## 7. Проверить шаблоны и Telegram

**Шаблон.** Открой **Сценарии → Библиотека шаблонов → Опубликовать версию**. Выбери базовый сценарий и нажми **Опубликовать**. Затем **Посмотреть шаблон → Название копии → Проект для копии → Создать из шаблона**. Откроется независимая копия. Измени её название, вернись в библиотеку и сравни с опубликованной версией. Если копируешь шаблон с расписанием, расписание копии изначально выключено.

**Telegram — по желанию.** Понадобятся токен твоего бота и chat ID диалога, где бот может писать. Открой диалог с ботом и нажми Start. Введи данные в **Настройки → Telegram**, нажми **Сохранить**, затем **Тест доставки**. Подтверждение — сообщение в выбранном чате. Чтобы проверить доставку именно из графа, в копии базового сценария добавь **Telegram**, соедини **Отчёт → Telegram** и запусти её. В чат придут число находок и ссылка на запуск. При локальной конфигурации ссылка localhost открывается на компьютере с запущенным CenterAI. Без бота можно пройти все предыдущие разделы.

## 8. Если результат отличается

| Что видишь | Что сделать |
| --- | --- |
| Браузер не открывает приложение | Запусти **Start-CenterAI.cmd** и дождись окончания сборки. Для первой установки нужен интернет. Адрес приложения — http://127.0.0.1:8000. |
| GitHub-источник отклонён | Проверь список **Настройки → Источники GitHub** или загрузи учебный проект через ZIP. Для ZIP лимит 24 МБ, нужен проект Gradle Kotlin DSL с исходниками в UTF-8. |
| Кнопка запуска недоступна | Нажми **Проверить**, прочитай сообщение над полотном. Проверь название, единственный триггер, входы узлов и наличие отчёта. |
| Находок больше или меньше 15 | Открой один конкретный запуск. Убедись, что использованы ZIP из раздела 1 и исходный граф с тремя анализаторами. Сними фильтры списка. |
| Появилась ошибка доставки | Открой журнал и отчёт: данные завершённого узла отчёта сохраняются. Проверь чат отдельно кнопкой **Тест доставки**. |
| Хочешь проверить удаление | Создай тестовую копию, удали её корзиной и подтверди. Для проверки удаления проекта используй отдельный тестовый проект: вместе с ним архивируются его сценарии. |

**Проверка пройдена**, если ты лично увидел завершённый запуск, открыл доказательство одной находки, скачал оба отчёта, получил ожидаемый результат фильтра, переключил ветвь условия и увидел самостоятельный запуск по расписанию. Чтобы закончить тест, выключи минутное расписание. При запуске через файл остановить сервер можно нажатием Ctrl+C в окне запуска.
