## 1. Первый запуск с известным ответом

1. Открой [CenterAI](http://127.0.0.1:8000). Если страница недоступна, в Проводнике открой папку `D:\Cybergarden` и дважды щёлкни **Start-CenterAI.cmd**. Дождись открытия браузера. Окно запуска оставь открытым.
2. Слева нажми **Проекты → Новый проект**. В поле **Название** введи `Repair Desk — ручной тест`. Описание можно оставить пустым.
3. Для воспроизводимого результата скачай [ZIP проверенной версии Repair Desk](https://github.com/TBagirov/training/archive/fe1fcbe212669783480666b9b60147c8a8c6eef4.zip). Выбери **ZIP → Выберите ZIP с проектом**, укажи скачанный файл и нажми **Создать проект**. Распаковывать его не нужно. Откроется карточка проекта.
4. Чтобы отдельно проверить импорт по ссылке, создай второй проект с другим названием. Выбери **GitHub**, оставь предложенную ссылку на `TBagirov/training` и нажми **Создать проект**. Этот способ берёт текущую версию репозитория. Дальше работай с первым проектом из ZIP.
5. В карточке первого проекта нажми **Создать сценарий**. Назови его `Базовая проверка`. В поле **Начальный граф** выбери **Три анализатора и отчёт**, затем **Открыть редактор**.
6. На полотне должны быть **6 узлов и 7 связей**. Ручной запуск ведёт к исходникам, оттуда идут три ветви к Secrets, SCA и SAST. Все три сходятся в отчёт.
7. Нажми **Проверить**. Ожидаемое сообщение — **Граф прошёл проверку**. Затем нажми **Запустить**. Откроется монитор. Дождись статуса **Завершён**.
8. Нажми **Результаты сессии** именно в этом запуске. На проверенном ZIP ожидаются **15 находок**: 5 SECRET, 5 SCA и 5 SAST. По критичности — 1 CRITICAL, 7 HIGH, 6 MEDIUM и 1 LOW. Обзор рабочего пространства суммирует результаты разных запусков, поэтому там число может быть больше.

## 2. Посмотреть доказательство и проверить экспорт

| Что нажать | Что проверить |
| --- | --- |
| **Открыть находки → Все анализаторы → SECRET** | Видно 5 строк. Нажми название или стрелку справа. В карточке есть путь, строка, факт анализатора и исправление. Значение секрета скрыто. |
| **Все анализаторы → SCA**, затем введи `jsoup` в поле **Путь, класс или advisory** | Останется зависимость jsoup. В подробностях видны её версия, идентификатор advisory и рекомендация. |
| Очисти поиск, верни **Все анализаторы**, выбери **Все уровни → CRITICAL** | Для этого запуска останется одна находка. **По пути** и **По критичности** меняют порядок. **Группировать** разделяет строки по анализаторам. |
| **Открыть запуск** в карточке находки или **Запуски → название сценария** | Монитор показывает граф именно выполненной версии, время и журнал событий. Раскрой **Данные этапов** и нажми идентификатор узла, чтобы увидеть его выход. |
| **Порядок исправлений → название находки** | Откроются подробности приоритетной проблемы. Базовые рекомендации даёт правило анализатора. После успешного этапа AI ниже появится дополнительное объяснение модели. |
| **JSON**, затем **TXT** в блоке результата | Перед кнопками должна быть надпись **Структура JSON проверена**. Открой оба файла из загрузок браузера. В JSON есть массив `findings` с 15 элементами, в TXT — те же результаты с текстовыми рекомендациями. [Образец JSON](example/submission.json) · [Образец TXT](example/report.txt) |

## 3. Карта экранов и кнопок

| Экран | Что делают элементы управления |
| --- | --- |
| **Главная** | **Загрузить репозиторий** открывает форму импорта и запуска. Счётчики ведут в соответствующие разделы, **История** — к запускам, уровень в блоке критичности — к отфильтрованным находкам. |
| **Проекты** | **Новый проект** импортирует ZIP или GitHub. Поиск и **Все источники** фильтруют список. Нажатие на строку открывает проект. **Изменить** меняет название и описание. **Сценарии проекта** показывает связанные графы. **Удалить** архивирует проект и его сценарии после подтверждения, история проверок сохраняется. |
| **Сценарии** | **Новый сценарий** предлагает готовый граф или **Только триггер**. Название открывает редактор. Значок двух листов **Скопировать** создаёт независимую копию, корзина удаляет сценарий после подтверждения, **Запуск** сразу запускает сохранённый граф. Выпадающий список фильтрует по проекту. |
| **Запуски** | Выбери проект и статус. Название сценария или стрелка открывают один запуск. **Назад / Далее** переключают страницы длинной истории. **Отменить запуск** доступна в очереди или во время выполнения. Уже начатый этап может успеть закончиться. На небольшом проекте весь запуск иногда завершается раньше, чем появится возможность нажать кнопку. |
| **Находки** | Боковое меню открывает результаты всего пространства. Переход из монитора ограничивает список одним запуском. Фильтры, поиск, группировка и кнопки подробностей описаны в разделе 2. |
| **Настройки** | Здесь можно выбрать тему и язык интерфейса. |

## 4. Как пользоваться редактором

Для экспериментов открой **Сценарии → Скопировать** у базовой проверки. Наведи указатель на кнопку без подписи, чтобы увидеть подсказку.

- **Добавить узел.** Нажми **Узлы**, найди тип через **Найти узел**, затем нажми его название или перетащи на полотно. Заголовки групп сворачивают и раскрывают палитру.
- **Соединить.** Перетащи линию от правого кружка первого узла к левому кружку второго. Есть и более точный способ: выбери **принимающий** узел, открой **Входящие связи**, в **Вход из узла** укажи предшественника и нажми **Соединить**. Для IF / ELSE дополнительно выбери **Ветвь → Да** или **Нет**.
- **Убрать связь.** В том же списке нажми корзину рядом с нужным предшественником. **Удалить узел** убирает выбранный узел вместе с его связями. Крестик **Свернуть инспектор** только закрывает панель.
- **Перемещаться.** Перетащи карточку за её тело. Перетаскивание фона двигает полотно, колесо мыши и кнопки **+ / −** меняют масштаб. **Весь граф** возвращает все узлы в поле зрения. Замок на панели полотна переключает доступность взаимодействия.
- **Сохранить.** Вверху можно изменить название. Шестерёнка **Настройки сценария** открывает описание. Дискета **Сохранить** сохраняет текущие изменения. При автосохранении дождись надписи **Сохранено**.
- **Проверить и выполнить.** **Проверить** проверяет связи и параметры. **Запустить** выполняет граф над файлами проекта. Для проверки ошибки добавь **Regex** и оставь его вход свободным: появится сообщение о неподключённом узле, запуск будет недоступен. Удали этот узел и проверь граф снова.
- **Вернуться к версии.** Измени название и сохрани. Нажми значок часов **Версии**, найди прежнее название, нажми **Загрузить** и дождись сохранения. Открой старый запуск: в его истории останется версия, с которой он выполнялся.

## 5. Проверить каждый тип узла своими руками

Базовый запуск уже проверил **Ручной запуск**, **Исходники**, **Secrets** (учётные данные), **SCA** (зависимости Gradle), **SAST** (код и настройки Kotlin) и **Отчёт**. Для каждого эксперимента ниже удобнее создавать новый сценарий на том же ZIP, выбрав **Только триггер**. Узлы добавляй и соединяй по инструкции выше.

| Узел в палитре | Что он делает с данными |
| --- | --- |
| **Ручной запуск** | Начальная точка графа. Кнопка **Запустить** создаёт выполнение. У узла нет входа и полей настройки |
| **Расписание** | Запускает тот же граф по пяти полям cron: минуты, часы, день месяца, месяц, день недели. Например, `0 9 * * 1-5` означает 09:00 с понедельника по пятницу в выбранной зоне. Включение, сохранение и проверка описаны в разделе 6 |
| **Исходники** | Передаёт обработчикам файлы снимка проекта, который выбран при создании сценария. В инспекторе узла повторно загружать файл не нужно |
| **Secrets** | Ищет встроенные пароли, ключи API, токены конфигурации, запасные значения, простые сборки токенов из фрагментов и закрытые ключи. Открой SECRET в находках, сверь класс и строку с файлом. Отображаемое доказательство маскирует значение |
| **SCA** | Разбирает поддерживаемые объявления Gradle Kotlin DSL, каталоги версий и lockfile. Сверяет версии библиотек с учебным снимком бюллетеней. В карточке SCA проверь координаты зависимости, версию, advisory и предлагаемое исправление |
| **SAST** | Ищет поддерживаемые конструкции Kotlin, связанные с SQL, проверкой TLS, CORS и авторизацией маршрута или отдельного объекта. В карточке SAST проверь указанную функцию и окружающий код. Для вывода о поведении работающего приложения требуется проверка контекста |
| **IF / ELSE** | В поле **Порог** укажи целое число от нуля. Операторы `>`, `>=`, `==`, `<`, `<=` сравнивают **число входных записей** с этим значением. Все входные записи идут по одному выбранному выходу. Для проверки условия по HIGH сначала добавь фильтр **Критичность** |
| **Критичность** | Галочками выбери хотя бы один из пяти уровней. Запись проходит, если её уровень входит в выбор. Чтобы пропустить HIGH и CRITICAL, отметь оба |
| **Regex** | Сравнивает выражение с относительным путём файла каждой находки. Точка в регулярном выражении означает произвольный символ, `[.]` — буквальную точку, `$` — конец пути. Пустое или некорректное выражение вызывает ошибку проверки графа |
| **AI-анализ** | Получает уже обнаруженные проблемы и запрашивает объяснения у выбранной модели. Подключай его после анализатора или фильтра и до отчёта. На пустом входе вызов модели пропускается. [Настройка и тест](#ai) |
| **Отчёт** | Объединяет входные находки по ID, проверяет их поля и сохраняет для карточек и экспорта. Для печатного результата скачай TXT, для машинной обработки — JSON |
| **Telegram** | Принимает выход отчёта и отправляет в настроенный чат краткую сводку. Параметры бота задаются через API. Назначение и проверка доставки описаны в разделе 7 |

| Эксперимент | Что собрать и выставить | Ожидаемый результат |
| --- | --- | --- |
| Фильтр критичности | **Ручной запуск → Исходники → SCA → Критичность → Отчёт**. У узла **Критичность** оставь галочку только у CRITICAL. | На выходе SCA — 5, в отчёте — 1. Сравни через **Данные этапов**. |
| Фильтр по пути | **Ручной запуск → Исходники → Secrets → Regex → Отчёт**. В поле **Выражение для пути** введи `application[.]yml$`. | Из пяти находок Secrets в отчёт проходит одна, в файле `src/main/resources/application.yml`. |
| Обе ветви IF / ELSE | **Ручной запуск → Исходники → Secrets → IF / ELSE**. Добавь два отдельных узла **Отчёт**. Один подключи к выходу **Да**, другой — к **Нет**. У условия выбери оператор `>` и порог `0`. Запусти. Затем поставь порог `5` и запусти снова. | В первом запуске условие `5 > 0` истинно, отчёт на ветви **Нет** пропущен. Во втором `5 > 5` ложно, пропущена ветвь **Да**. Число находок в обоих отчётах одинаковое. Разницу смотри в **журнале и статусах узлов**. |

Если встраиваешь фильтр в готовый граф, удали прямую связь между анализатором и отчётом, которую он заменяет. Иначе часть данных дойдёт до отчёта в обход фильтра.

## 6. Проверить автоматический запуск

1. Скопируй базовый сценарий, пока у него ручной триггер. Назови копию `Тест расписания`.
2. Удали **Ручной запуск**. Добавь **Расписание** и соедини его с **Исходники**. В графе должен быть один триггер.
3. У узла укажи **Cron** `* * * * *` и **Часовой пояс** `Europe/Moscow`. Включи **Включить расписание**, сохрани граф.
4. Оставь сервер включённым. После ближайшего времени по заданному cron открой или обнови **Запуски**. Должна появиться новая запись без ручного запуска.
5. В редакторе выбери узел **Расписание**, отключи **Включить расписание** и сохрани граф. Уже созданные записи останутся в истории.

## 7. Проверить шаблоны и Telegram

**Шаблон.** Открой **Сценарии → Библиотека шаблонов → Опубликовать версию**. Выбери базовый сценарий и нажми **Опубликовать**. Затем **Посмотреть шаблон → Название копии → Проект для копии → Создать из шаблона**. Откроется независимая копия. Измени её название, вернись в библиотеку и сравни с опубликованной версией. Если копируешь шаблон с расписанием, расписание копии изначально выключено.

**Telegram — по желанию.** Понадобятся токен твоего бота и chat ID диалога, где бот может писать. Открой диалог с ботом и нажми Start. В `/docs` введи токен и chat ID в поля `token` и `chat` метода `PUT /api/v1/integrations/telegram`. Для теста доставки выполни `POST /api/v1/integrations/telegram/test`. Подтверждение — сообщение в выбранном чате. Чтобы проверить доставку именно из графа, в копии базового сценария добавь **Telegram**, соедини **Отчёт → Telegram** и запусти её. В чат придут число находок и ссылка на запуск. При локальной конфигурации ссылка localhost открывается на компьютере с запущенным CenterAI. Без бота можно пройти все предыдущие разделы.

## 8. Если результат отличается

| Что видишь | Что сделать |
| --- | --- |
| Браузер не открывает приложение | Запусти **Start-CenterAI.cmd** и дождись окончания сборки. Для первой установки нужен интернет. Адрес приложения — http://127.0.0.1:8000. |
| GitHub-источник отклонён | Проверь URL или загрузи учебный проект через ZIP. Для ZIP лимит 24 МБ, нужен проект Gradle Kotlin DSL с исходниками в UTF-8. |
| Кнопка запуска недоступна | Нажми **Проверить**, прочитай сообщение над полотном. Проверь название, единственный триггер, входы узлов и наличие отчёта. |
| Находок больше или меньше 15 | Открой один конкретный запуск. Убедись, что использованы ZIP из раздела 1 и исходный граф с тремя анализаторами. Сними фильтры списка. |
| Появилась ошибка доставки | Открой журнал и отчёт: данные завершённого узла отчёта сохраняются. Проверь чат отдельно кнопкой **Тест доставки**. |
| Хочешь проверить удаление | Создай тестовую копию, удали её корзиной и подтверди. Для проверки удаления проекта используй отдельный тестовый проект: вместе с ним архивируются его сценарии. |

**Проверка пройдена**, если ты лично увидел завершённый запуск, открыл доказательство одной находки, скачал оба отчёта, получил ожидаемый результат фильтра, переключил ветвь условия и увидел самостоятельный запуск по расписанию. Чтобы закончить тест, выключи минутное расписание. При запуске через файл остановить сервер можно нажатием Ctrl+C в окне запуска.

## 9. Как подключить нейросеть и увидеть её ответ

### Локальная модель на Windows

**Быстрый путь для уже настроенной модели.** Открой **Сценарии → Новый сценарий → Начальный граф → Три анализатора, AI и отчёт → Открыть редактор**. Должны появиться семь узлов и восемь связей. Нажми **Проверить → Запустить**. Ниже — способ проверить всё с нуля, сначала на одной находке.

1. Сначала выполни базовый запуск из раздела 1. Так ты запишешь результат обычных анализаторов и сможешь сравнить его с запуском через AI.
2. Установи и открой Ollama, если она ещё не установлена. В новом окне PowerShell выполни команды ниже. Первая показывает установленные модели. Вторая понадобится для загрузки модели из примера, если её ещё нет. Имя уже установленной модели тоже можно использовать. [Ollama для Windows](https://docs.ollama.com/windows)

   ```powershell
   ollama list
   ollama pull qwen3:4b
   Invoke-RestMethod http://127.0.0.1:11434/api/tags
   ```

3. Открой **Сценарии → Новый сценарий**. Выбери проект Repair Desk, название `Проверка AI на одной зависимости` и **Только триггер → Открыть редактор**.
4. Нажми **Узлы** и собери эту цепочку слева направо. Для каждой стрелки можно выбрать правый узел и указать левый в поле **Вход из узла**.

   **Ручной запуск → Исходники → SCA → Критичность → AI-анализ → Отчёт**

5. Выдели **Критичность**. Оставь только **CRITICAL**. В результате контрольного проекта через этот фильтр проходит одна зависимость. Это удобный первый запрос к локальной модели.
6. Выдели **AI-анализ**. В поле **Модель** впиши точное имя из `ollama list`, включая тег после двоеточия. Пустое поле использует серверную переменную `AI_MODEL`, по умолчанию `qwen3:4b`. Название сохраняется вместе с версией графа.
7. Нажми **Проверить → Запустить**. В мониторе дождись окончания этапа. При первом запросе Ollama может потратить время на загрузку весов в память. В панели результата найди название модели и **Объяснения готовы**.
8. Нажми **Результаты сессии**, затем стрелку у зависимости. Сверху расположены путь, строка и факт анализатора. Ниже, в **Объяснение AI**, прочитай технические детали, возможные последствия, шаги исправления и оговорку о ложном срабатывании. Сверь рекомендацию с бюллетенем зависимости.
9. Вернись в монитор через **Открыть запуск**. Раскрой **Данные этапов**, нажми идентификатор AI-узла. Поле `ai` содержит модель, провайдера, версию системного промпта и статус. При успехе там есть резюме, приоритетные действия и ограничения. В скачанном **TXT** появятся объяснение и шаги. **JSON** сохраняет формат организаторов.
10. Чтобы проверить все три анализатора, скопируй базовый сценарий. В инспекторе **Отчёт → Входящие связи** удали три прежние связи. Подключи каждый анализатор ко входу **AI-анализ**, а его выход к **Отчёт**. Запусти повторно. На контрольном ZIP ожидаются те же 15 находок. Модель получает группы до трёх записей.

### Если модель работает на другом сервере

Провайдер и адрес задаёт оператор при старте приложения. Модель можно переопределить для отдельного узла. Сервер должен поддерживать структурированный ответ по JSON Schema. Для облачного сервиса на него отправятся категории, классы, критичность, идентификаторы находок и метаданные зависимостей. Пути, номера строк, исходный код, фрагменты доказательств и значения найденных секретов остаются в CenterAI.

| Переменная | Что задать |
| --- | --- |
| `AI_PROVIDER` | `ollama` для API Ollama или `openai-compatible` для сервера с Chat Completions |
| `AI_BASE_URL` | Для Ollama по умолчанию `http://127.0.0.1:11434`. Для совместимого API укажи базовый адрес из его настроек, обычно с окончанием `/v1`. Суффикс метода добавляет CenterAI |
| `AI_MODEL` | Точное имя установленной или доступной в учётной записи модели |
| `AI_API_KEY` | Ключ совместимого API, если провайдер требует авторизацию. Его вводят в окружение процесса. Он не нужен локальной Ollama |

Для обычного запуска Windows останови прежний сервер в его окне через **Ctrl+C**. Открой PowerShell в папке проекта, задай переменные и запусти приложение из **этого же окна**. Пример для локальной Ollama:

```powershell
Set-Location D:\Cybergarden
$env:AI_PROVIDER = 'ollama'
$env:AI_BASE_URL = 'http://127.0.0.1:11434'
$env:AI_MODEL = 'qwen3:4b'
.\Start-CenterAI.cmd
```

Для Docker Compose укажи переменные в локальном `.env` и выполни `docker compose up -d --build`. Модель вызывает контейнер worker. Если Ollama работает на Windows-хосте с Docker Desktop, ему нужен доступный с контейнера адрес, например `http://host.docker.internal:11434`. Проверь настройки прослушивания Ollama. Внутри контейнера адрес 127.0.0.1 указывает на сам контейнер.

### Как читать результат AI

| Что видишь | Что произошло и как проверить самому |
| --- | --- |
| **Объяснения готовы**, статус `ok` | Сервер принял структуру ответа и сопоставил каждое объяснение с входной находкой. Сверь идентификатор бюллетеня, рекомендуемую версию и применимость совета к своему коду |
| `SUPPORTED` | По оценке модели переданных метаданных достаточно для пояснения. Доказательство анализатора и расположение показаны отдельно |
| `INSUFFICIENT_EVIDENCE` или `MISMATCH` | Модель сообщает о нехватке или несогласованности сведений. Прочитай оговорку, открой файл на указанной строке и проверь контекст вручную |
| **Нет находок для объяснения** | До узла дошёл пустой набор. Для проверки оставь только INFO в фильтре контрольного проекта. Запрос к модели не требуется |
| **Объяснения получены для части находок** | Модель вернула корректные результаты для части групп. Открой карточки, чтобы прочитать принятые пояснения. В отчёте остаются все исходные находки |
| **Модель недоступна или ответ не прошёл проверку** | Проверь адрес, доступное имя модели и поддержку схемы. Для воспроизведения на Ollama впиши в копии графа несуществующее имя модели и запусти. Сканер по-прежнему вернёт свою находку, в карточке останется его рекомендация |
| **Проверьте настройки провайдера** | Проверь написание `AI_PROVIDER` и наличие базового адреса для совместимого API. Перезапусти процесс после изменения переменных |
| **Не удалось подтвердить исходные данные** | Сервер отклонил входные метаданные. Сравни путь и строку в результате анализатора с импортированным снимком |
| Узел вообще отсутствует в палитре | Проверь, что открыт обновлённый backend. В `/api/v1/registry` должен присутствовать `ai_analysis`. Повторный щелчок по файлу запуска при работающем старом сервере открывает прежний процесс |

## 10. Справочник экранов, полей и состояния данных

**Проект** хранит снимок исходников. **Сценарий** хранит граф для выбранного проекта. **Версия** фиксирует его сохранённое состояние. **Запуск** исполняет одну версию и хранит собственные результаты. Один проект может иметь несколько сценариев, у каждого может быть много запусков. Если ты исправил код и хочешь сравнить до и после, импортируй исправленную версию как второй проект и перенеси граф через библиотеку шаблонов.

| Где ты находишься | Что можно сделать и как увидеть результат |
| --- | --- |
| Левое меню, логотип, верхняя строка | Логотип открывает обзор. Пункты меню переключают шесть основных разделов. Верхняя строка показывает текущий раздел. В диалоге крестик или Esc закрывает окно. Крестик в сообщении закрывает только уведомление |
| **Главная → Загрузить репозиторий** | Выбери архив или публичную ссылку GitHub и профиль проверки. Можно перетащить архив прямо на страницу, чтобы открыть ту же форму с выбранным файлом. Нажми **Запустить проверку**, чтобы импортировать проект и открыть монитор |
| **Главная → Проекты / Сценарии / Запуски / Находки** | Число на карточке относится ко всему рабочему пространству. Нажми число для перехода к списку. **Последние запуски** открывает отдельные результаты. Полоска уровня критичности открывает список с этим уровнем |
| **Новый проект → Название / Описание** | Название обязательно, до 100 символов. Описание до 2000 символов помогает различать снимки. В режиме ZIP после выбора файла появятся имя и размер. После отправки сначала виден прогресс загрузки, затем проверка исходников |
| **Новый проект → GitHub** | Введи ссылку вида `https://github.com/owner/repo` из разрешённого списка. Сервер получает снимок текущей основной ветки. Для точного повтора версии используй ZIP из раздела 1 |
| **Карточка проекта** | **Источник** показывает тип и имя архива или адрес. **Файлы для проверки** показывает число отобранных файлов. **Последний запуск** и таблица **Проверки проекта** относятся только к этому проекту. **Изменить → Сохранить** меняет название и описание |
| **Новый сценарий** | Выбери проект, введи название, задай начальный граф. **Только триггер** — начало для своего графа. Для запуска добавь хотя бы источник, анализатор и отчёт. **Три анализатора и отчёт** даёт сразу рабочий пример |
| **Сценарии → копия / шаблон / версия** | Две страницы создают отдельную копию сценария. **Версии → Загрузить** переносит прежнее состояние в текущий редактор. **Опубликовать версию** фиксирует граф в локальной библиотеке. **Проект для копии** в шаблоне позволяет применить его к другому снимку |
| **Редактор → инспектор** | Выбери карточку на полотне. Под описанием видны тип, вход и выход. В **Входящие связи** перечислены предшественники. Если названия совпадают, различай узлы по окончанию ID в списке. Щелчок по пустому полотну закрывает инспектор. Delete или Backspace на выделенном элементе удаляет его |
| **Редактор → название / описание / версия** | Название редактируется в верхней строке. Шестерёнка открывает **Описание**, кнопка **Готово** возвращает на полотно. Перед уходом проверь индикатор сохранения и номер версии. Если другой редактор уже изменил сценарий, перечитай актуальную версию перед повторной правкой |
| **Монитор → Выполнение графа** | Счётчик показывает ход выполнения, у карточек видны статусы. Граф здесь служит для просмотра. Для изменения вернись в **Сценарии**. Время создания и номер версии вверху помогают отличать запуски с одинаковым названием |
| **Монитор → Журнал событий** | Читай события по времени. Для узла указаны название и ID. Закрытую вкладку можно открыть снова через историю. При **Ошибка** проверь последнее сообщение и узел, на котором остановилась проверка |
| **Монитор → Данные этапов** | Нажми ID. У источника поле `files` показывает число файлов. У анализатора `count` и `ids` описывают выход, `findings` — новые находки этапа. У условия `branch` содержит `true` или `false`. У Telegram успешная доставка записана в `receipt`. У AI открой `ai` |
| **Монитор → Проверка перед экспортом** | Сверь количество записей и число высоких и критических проблем. **Порядок исправлений** показывает до пяти приоритетных записей. При досрочном завершении панель предупреждает о частичном отчёте. В него входят результаты уже завершившихся узлов **Отчёт** |
| **Находки → список / карточка** | Фильтры категории, критичности и поиска применяются вместе. Очисти строку и верни оба списка к значению **Все**, чтобы увидеть полный набор. Стрелка строки открывает карточку. **Открыть запуск** возвращает к источнику конкретной записи. В глобальном списке одна проблема может встретиться повторно после нескольких запусков |
| **Настройки → Внешний вид** | Выбери тему и язык интерфейса. Выбор сохраняется в браузере. |

### Статусы и выходы узлов

| Статус | Как его интерпретировать |
| --- | --- |
| Без запусков | Для сценария ещё нет записи выполнения |
| В очереди / Ожидание | Запуск принят или узел ждёт своей очереди. Можно открыть другую страницу и вернуться через историю |
| Выполняется | Работает обработчик. **Отменить запуск** запрашивает остановку. До завершения текущего этапа может отображаться **Завершается этап…** |
| Пропущен | Ветвь условия не выбрана или последующие узлы не выполнялись после ошибки. Для IF / ELSE смотри значение `branch` предшественника |
| Завершён | Обработка закончилась штатно. Для AI отдельно проверь, удалось ли получить объяснения |
| Ошибка / Отменён | Открой журнал и предпросмотр частичного отчёта. Чтобы повторить, открой сценарий и создай новый запуск |

**Как соединять порты.** Триггер выдаёт `start`, источник принимает его и выдаёт `files`. Каждый анализатор принимает файлы и выдаёт `findings`. Несколько анализаторов можно поставить параллельно или последовательно. Логика и AI принимают и возвращают находки. **Отчёт** принимает находки и выдаёт `report`. **Telegram** принимает отчёт и выдаёт квитанцию `receipt`. У **IF / ELSE** активна одна ветвь. Чтобы сохранить результаты нескольких анализаторов, подведи их к общему отчёту. Одинаковые ID объединяются.

**Что проверяет импорт.** Архив ограничен 24 МиБ, суммарный распакованный объём — 48 МиБ, число записей — 4000, размер отдельного учитываемого файла — 512 КиБ. Сервис ищет корень по `settings.gradle.kts` или `build.gradle.kts`, читает поддерживаемые текстовые файлы UTF-8 и пропускает служебные каталоги, включая `build`, `.git` и `ground-truth`. Счётчик файлов может быть меньше числа записей в ZIP.

## 11. Проверка через API и CI

Открой [интерактивный справочник API](http://127.0.0.1:8000/docs). На тестовом порту используй тот же путь `/docs`. Раскрой метод, нажми **Try it out**, заполни поля и нажми **Execute**. Внизу появятся код ответа и содержимое. Начни с читающих методов.

| Что проверить | Метод и ожидаемое содержимое |
| --- | --- |
| Типы узлов и параметры | `GET /api/v1/registry` — палитра, контракты портов, значения по умолчанию и базовый граф |
| Проекты, сценарии, версии | `GET /api/v1/projects`, `GET /api/v1/workflows`, `GET /api/v1/workflows/{key}/versions`. Подставляй полный ID из адреса карточки |
| Запуск и журнал | `POST /api/v1/workflows/{key}/runs` создаёт новый запуск. Используй возвращённый ID в `GET /api/v1/runs/{key}`. Поле `nodes` показывает этапы, `events` — журнал. Для обновлений во время исполнения приложение использует путь `/runs/{key}/events` с префиксом API |
| Выход AI или другого узла | `GET /api/v1/runs/{key}/nodes/{node_id}`. Возьми точный ID узла из **Данные этапов** |
| Результаты | `GET /api/v1/findings?run_id=…` возвращает подробные записи. `GET /api/v1/runs/{key}/report/preview` показывает сводку, `/report?format=json` и `/report?format=txt` отдают файлы |

В PowerShell из папки проекта подставь реальный ID своего сценария. Скрипт создаст запуск, дождётся его и запишет два файла в выбранный каталог.

```powershell
.\.venv\Scripts\python.exe scripts\ci_scan.py --workflow ID_СЦЕНАРИЯ --output .qa\my-reports
```

Параметр `--url` задаёт адрес сервера, `--timeout` — время ожидания в секундах. Для медленной локальной модели увеличь значение относительно стандартных 180 секунд. `--archive` импортирует новый ZIP и создаёт отдельную копию графа с выключенным расписанием. `--fail-on HIGH` завершает команду с ошибкой при HIGH или CRITICAL после записи отчётов. Это способ использовать те же проверки в CI.

## 12. Как завершить личную проверку

Сохрани для сравнения TXT и JSON базового запуска. Зафиксируй номера двух запусков IF / ELSE с разными порогами, одного запуска по расписанию и запуска с AI. В истории открой каждую запись и сравни граф, версию, статус и выход нужного узла. Для Telegram подтверждением служит сообщение в выбранном чате. Для AI подтверждением вызова с принятым ответом служат статус **Объяснения готовы** и блок пояснения в карточке. Затем отключи тестовое минутное расписание. Тестовые копии можно архивировать через соответствующий список, а завершённые запуски останутся в истории.

## 13. Рабочий стенд с локальной моделью и CI

**Запуск.** На Windows x64 открой `Start-CenterAI-Demo.cmd` и оставь окно открытым. Стенд скачает компактную модель и запустит [CenterAI](http://127.0.0.1:8002). Модель работает на CPU. Веса хранятся в `.qa/model`. Обычный запуск с установленной Ollama выполняется через `Start-CenterAI.cmd`.


**Построить схему словами.**

1. Если проектов пока нет, импортируй контрольный ZIP из раздела 1.
2. В **Сценарии → Новый сценарий** введи название и выбери проект. В **Начальный граф** выбери **По описанию с AI**.
3. В поле **Что проверить** попробуй: «Вручную проверь зависимости Gradle. Оставь только CRITICAL. Объясни результаты с помощью AI и сформируй отчёт».
4. Нажми **Открыть редактор** и дождись ответа. Генератор получает только текст задания. Сервис переводит предложенный план в разрешённые узлы, проверяет граф и сохраняет сценарий. При ошибке модели форма остаётся открытой.
5. **Проверь смысл черновика:** ожидаемые узлы — ручной запуск, исходники, SCA, критичность CRITICAL, AI-анализ, отчёт. Проверь уровни и связи в инспекторе. Если модель добавила ненужный шаг или пропустила нужный, отредактируй граф. Для запроса «по будням в 9 утра по Москве» отдельно сверь cron и зону. Календарный триггер в черновике всегда выключен.
6. Нажми **Проверить → Запустить**. После завершения открой находку и прочитай блок модели. При необходимости добавь Telegram после отчёта и настрой бота в разделе **Настройки**.

**Запуск из CI.** Используй команду из раздела 11. Укажи ID сценария, адрес доступного runner экземпляра CenterAI и порог через `--fail-on`. Отчёты сохраняются до применения порога.
