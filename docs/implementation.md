# Что реализовано и почему

## Путь пользователя

Пользователь регистрирует снимок учебного проекта, выбирает сценарий, настраивает граф и запускает проверку. Монитор открывает именно ту версию графа, которая попала в очередь. Результаты анализа доступны в истории после переименования проекта или редактирования сценария.

| Область | Что сделано | Для чего |
| --- | --- | --- |
| Импорт | ZIP и снимок default-ветки разрешённого GitHub-репозитория, поиск корня Gradle Kotlin DSL | Идентичный набор анализаторов работает с локальным архивом и с репозиторием. Внешняя оболочка архива не попадает в пути отчёта |
| Безопасное чтение | Файлы разбираются в памяти. Проверяются пути, symlink, шифрование архива, число и размеры записей. Ограничен размер входного HTTP-запроса | Сервису не требуется распаковывать пользовательские пути или исполнять сборку проекта |
| Хранение | SQLAlchemy 2, миграции Alembic, ключ Fernet и шифрование снимков и параметров Telegram | Исходники и токены защищены в резервной копии БД при отдельном хранении ключа |
| Интерфейс | React, TypeScript, Vite, React Router, TanStack Query, Zustand, Tailwind и локальные компоненты. Светлая рабочая область, типографика IBM Plex, граф на точечной сетке | Граф, журнал и находки требуют разной компоновки. Цвет уровня риска и статуса всегда сопровождается текстом |
| Граф | React Flow, палитра, drag-and-drop, соединения, инспектор, сохранение черновика, история версий, восстановление и защита от конфликтов | Оператор видит и меняет реальный граф. Два открытых редактора не могут молча затереть сохранённые изменения |
| Исполнение | Реестр типов с контрактами портов, собственный DAG-движок, топологический порядок, сравнения, ветвления и фильтры | Каждый этап получает данные только от активных предшественников. При слиянии одинаковые находки объединяются по идентификатору |
| Фоновые задачи | Очередь запусков в БД, атомарное получение работы, планирование по cron в IANA-зоне, отдельные службы в Compose | Закрытие вкладки не останавливает анализ. Поставленная в очередь работа переживает перезапуск. Просроченное выполнявшееся задание отмечается ошибкой |
| Монитор | Отдельные записи этапов, журнал с увеличивающимся ID, поток SSE с возобновлением | Оператор видит завершённые, пропущенные и ошибочные этапы. События можно перечитать после разрыва соединения |
| Анализаторы | Secrets, SCA и SAST возвращают единую внутреннюю модель | Одинаковая фильтрация, обработка уровней и навигация применяются ко всем категориям |
| Отчёты | Валидатор Pydantic и отдельный экспортёр формата организаторов. JSON, TXT, список находок и карточки доказательств | В машинный файл попадают только допустимые поля. Тексты исправлений связаны с правилом и наблюдаемым фактом |
| Telegram | Настройка подключения, тестовое сообщение и отдельный узел доставки | Сценарий может сообщить результат после формирования отчёта. Ошибка внешнего канала фиксируется отдельно на этапе доставки |

## Архитектурные решения

### Ревью ветки ai-backend

Проверена ревизия `c93d500`. Ветка добавляет самостоятельный сервер в `local-ai-backend/`. Её шесть тестов прошли в отдельном временном каталоге. Они покрывают хранение, граф, календарь, сохранение отчёта при сбое уведомления и Gradle lockfile. Качество советов реальной модели эти тесты не измеряют.

| Предмет проверки | Наблюдение и решение для основного приложения |
| --- | --- |
| Контракт с моделью | Адаптеры Ollama и OpenAI-compatible передают JSON Schema. Pydantic проверяет ответ. Валидатор требует одно объяснение на ID и проверяет упомянутые CVE. Эти части перенесены в `backend/ai_report.py` |
| Данные и достоверность | Модель получает ограниченный набор полей. Проверка упоминаний файлов в свободном тексте эвристическая. Качество совета, обоснованность бизнес-последствий и точность оценки SUPPORTED требуют экспертной проверки. Подлинные путь и строку выдаёт основной backend из снимка проекта |
| Несовместимость серверов | Ветка использует другой API загрузки, собственные SQLite, граф и очередь. Прямое переключение frontend нарушило бы работу существующих сценариев. Новый тип узла встроен в реестр основного графа и использует его историю, фильтры и экспорт |
| Поведение при сбое | После повторной неудачной попытки валидации исходные находки сохраняются. При обработке нескольких групп принятые объяснения сохраняются со статусом partial, если другие группы не прошли проверку. Модель, версия промпта и статус сохраняются в выходе узла |
| Что проверено при переносе | Тесты проходят от создания сценария через worker до записей находок и двух форматов экспорта. Проверены принятый ответ, неизвестный ID, посторонний CVE, придуманная строка и недоступный провайдер. Отдельный локальный HTTP-тест сверяет адрес метода, схему и передачу ключа у двух адаптеров |

При первоначальной проверке с выключенной Ollama приложение сохранило 15 находок и статус `ai_unavailable`. Затем на этой машине развернули llama.cpp с Qwen2.5-1.5B-Instruct и локальный SMTP-приёмник Mailpit. В браузере проверены генерация схемы из описания, запуск на Repair Desk, объяснение одной критической зависимости и приём письма. Маленькая модель может ошибиться в выборе условий или дать общий совет. Черновик доступен для редактирования до запуска, исходные данные анализатора отображаются рядом с объяснением. [Порядок личной проверки](manual-testing.md#demo)

**Рабочее пространство.** Выбран локальный однопользовательский режим из предложенных в ТЗ. Он позволяет запустить приложение на ноутбуке и загрузить учебный архив без настройки пользователей. Доступ извне требует отдельного решения по аутентификации.

**Два режима исполнения.** В Compose используется PostgreSQL, Redis и Celery. Для запуска непосредственно на Windows предусмотрены SQLite и локальный обработчик. Оба режима проходят через общие модели, валидацию, очередь и функции анализаторов. Для одного рабочего пространства в локальном режиме нужен один процесс Uvicorn.

**Импорт по ссылке.** Сервис получает архив с фиксированного хоста GitHub codeload и разрешает только пары owner/repo из конфигурации. Это даёт снимок исходников без истории, хуков и выполнения Git/Gradle-команд. Проверяемый снимок остается привязанным к проекту.

**Версии и история.** Project хранит метаданные и зашифрованный снимок. Workflow связан с Project и имеет последовательность WorkflowVersion. При запуске создаётся Run с названиями, номером версии и собственной копией графа. NodeRun, Event и Finding ссылаются на Run. Пара run_id/fingerprint уникальна для итоговой находки. Удаление проекта или сценария архивирует запись и отключает её расписание. Миграции содержат точные типы, индексы и ограничения.

**Границы анализа.** SCA разбирает явные Gradle-зависимости, локальные версии, свойства, lockfile и поддерживаемые записи каталога TOML. Числовые компоненты версий сравниваются с учётом открытых и закрытых границ. SAST использует Tree-sitter Kotlin для выделения функций и собственные проверки контекста SQL, TLS, CORS, политик маршрутов и чтения записей. Это ограниченный статический анализ. Динамическое построение маршрутов, произвольное вычисление версий и полное межпроцедурное доказательство прав доступа выходят за его возможности. Secrets различает литералы, ссылки на окружение, встроенные резервные значения и простые сборки токена из фрагментов.

**Канал уведомлений.** Выбран предложенный в ТЗ Telegram. Сохранённый токен отсутствует в ответах API. Провайдер передаёт число находок и ссылку на запуск. Повторный сетевой запрос при неопределённом ответе не выполняется автоматически, чтобы не отправить отчёт дважды.

**Интерфейс.** Обзор показывает реальные счётчики и последние запуски. Редактор организован вокруг полотна, палитры и инспектора. Реестр backend поставляет клиенту названия, типы портов, описания и исходные параметры. Таблицы и ленты используют общие компоненты статусов. Размеры шрифтов и цветовые состояния собраны в общей таблице стилей. Основные шрифты включены в сборку.

## Движение данных

```text
React → REST API → БД проектов, графов и версий
                      ↓
Ручной запуск / срок cron → очередь Run → DAG → исходники → анализаторы
                                                   ↓
                                       условия и фильтры → отчёт → Telegram
                                                              ↓
                      интерфейс ← REST / SSE ← этапы, события и находки
```

В графе можно последовательно запускать анализаторы или сводить несколько независимых ветвей в узле отчёта. Узлы условий выбирают выход по числу находок. Пропуск распространяется только по неактивной ветви. Каждая обработанная ветвь отчёта добавляет в итог уникальные записи.

## Что проверено

### Приёмка P0, P1 и P2 после интеграции

| Приоритет | Возможности | Как проверить и границы |
| --- | --- | --- |
| P0 | Импорт ZIP или разрешённого GitHub-репозитория, визуальный граф, ручной и календарный запуск, IF / ELSE, сравнение количества, фильтры критичности и пути, передача результатов и монитор | На контрольном Repair Desk исходный граф даёт 15 записей. Изменение порога переключает активную ветвь. Календарь использует сохранённую зону |
| P0 | Классификация риска и три собственных анализатора для Kotlin/Spring Boot с Gradle Kotlin DSL | На открытом эталоне найдены 5 SECRET, 5 SCA и 5 SAST. Учебный снимок базы SCA и набор статических правил ограничивают покрытие |
| P0 | AI-объяснения, рекомендации и проверка достоверности | На Windows-стенде настоящая модель обработала CRITICAL-находку по commons-text. Проверяются ID, схема, допустимые CVE, расположение в исходниках и язык пояснения. Оценка технической корректности свободного текста остаётся за разработчиком |
| P0 | Канал уведомления | Проверен путь «завершённый отчёт → SMTP → письмо в Mailpit» с количеством находок и ссылкой. Для внешнего почтового ящика нужен SMTP провайдера. Для проверки реального Telegram-чата нужны бот и chat ID |
| P1 | История, защищённое хранение, модульность, выбор провайдера, расширение палитры | Снимок запуска и версии сохраняются. Учётные данные Telegram и адрес почтового получателя хранятся зашифрованными. Пароль SMTP и ключ облачного провайдера получает процесс из окружения. Реестр узлов используется редактором и исполнителем |
| P2 | Библиотека, публикация, независимая копия | Шаблон хранит конкретную версию графа. Выбор проекта при копировании меняет снимок, которому будет передан этот граф |
| P2 | CI/CD с настройками | В настройках можно выбрать сценарий, порог завершения с ошибкой и время ожидания. Команда запускает реальный сценарий и пишет JSON и TXT до применения порога |
| P2 | Генерация Workflow по тексту | Модель предлагает план из поддерживаемых анализаторов, фильтров, условия, расписания, объяснения и каналов. Backend собирает и проверяет граф. Оператор видит черновик до запуска. Планировщик в черновике отключён |

- **Эталон организаторов.** Тест загружает ground truth только из тестового каталога. Для SECRET и SAST учитываются категория, класс, путь и попадание строки в эталонный диапазон. Для SCA проверяются путь, координаты, версия и допустимый advisory. Каждое совпадение засчитывается один раз. Отдельно проверяются отрицательные контроли.
- **Анализаторы.** Проверены границы числовых версий, перекрытие версии lockfile, каталог Gradle, маскирование секрета, комментарии, резервное значение на следующей строке и различие SQL-подстановки и параметризации.
- **API и исполнитель.** Пройдены создание проекта, импорт ZIP, редактирование, версионирование, отказ при конфликте, отклонение некорректного графа, ручной и календарный запуск, IF / ELSE, фильтры, SSE, экспорт и сохранение истории. Тесты безопасности входов проверяют обход пути, symlink и отказ для недопустимого адреса.
- **Интерфейс.** Компонентные тесты проверяют пустую историю и текстовый статус пропущенной ветви. Playwright проверяет загрузку ZIP, редактирование и запуск графа, просмотр находки, скачивание отчёта, настройки и мобильную ширину.
- **Внешние зависимости.** Реальный импорт GitHub проверен на официальном наборе. Для Telegram использован подменённый транспорт в тесте и отдельно проверена ошибка при отсутствии настроек. Контейнерный стек прошёл проверку в GitHub Actions на Linux, включая реальный cron, SSE и экспорт.

Оба экспортированных файла сохранены в репозитории. Они получены при импорте ZIP и запуске базового графа через API. Оператор может повторить тот же путь в браузере. [JSON](example/submission.json) · [Текстовый отчёт](example/report.txt)
