Cyber Garden — локальный backend

Запуск на Windows

1. Распакуйте архив. На ноутбуке, где уже работает локальная Qwen3 4B, запустите Ollama.
2. Дважды нажмите start_backend.cmd. Оставьте окно открытым. Проверка состояния — http://127.0.0.1:8765/api/v1/health.
3. Дважды нажмите run_demo.cmd. Скрипт создаст учебный проект, сохранит граф и запустит его. В конце он напечатает адрес HTML-отчёта. Откройте его в браузере. История остаётся в каталоге data при перезапуске. Для остановки сервера нажмите Ctrl+C.
4. На другой машине понадобятся Python 3.10+, Pydantic 2 и cryptography. Команда python -m pip install -r requirements.txt также устанавливает FastAPI, Uvicorn и tzdata. Оллама должна содержать модель qwen3:4b. Установка весов командой ollama pull qwen3:4b.

Данные и исполнение

Сервис принимает текстовые исходники внутри ZIP-архива или одну разрешённую ссылку на учебный репозиторий. ZIP читается в памяти с ограничениями размера. Gradle и исходники проекта не выполняются. Проект хранится зашифрованным в SQLite. Для резервной копии при остановленном сервере сохраните весь каталог data вместе с source.key. У ключа тот же уровень доступа ОС, что и у рабочего каталога. Сервис рассчитан на одно локальное рабочее пространство. Сетевую аутентификацию и режим нескольких пользователей не проверяли.

Граф задаётся массивами nodes и edges. Узлы имеют id, type и при необходимости config. Рёбра содержат source, target и для выходов if_else поле branch со значением true или false в виде строки. Получите готовый граф через GET /api/v1/nodes. Сервер проверяет граф, создаёт новую версию при изменении и исполняет узлы в топологическом порядке. SQLite хранит версию, события и отчёт каждого запуска. На CPU одновременно выполняется один workflow, остальные ждут в очереди. После прерывания процесса незавершённые запуски помечаются failed.

Значения узлов

manual_trigger и schedule_trigger задают способ запуска. repository_source передаёт снимок загруженного проекта. secrets, sca и sast статически проверяют исходники и зависимости. severity_filter принимает config.severity. regex_filter принимает config.pattern для проверки пути (регулярное выражение Rust regex, максимум 256 символов). if_else сравнивает число находок выбранной критичности с config.min_count. Условия отрабатывают на данных активных предшественников. ai_analysis вызывает локальную Ollama и проверяет структуру ответа и ID. report формирует JSON для сдачи и данные для HTML. notification отправляет краткое сообщение HTTP POST. Чтобы сохранить отчёт при недоступной LLM, данные анализаторов идут вместе с состоянием AI. При сбое канала доставки ранее сформированный отчёт доступен по ID запуска.

Подключение frontend

Базовый адрес http://127.0.0.1:8765/api/v1. Разрешённые origin для локального Vite — http://localhost:5173 и http://127.0.0.1:5173. JSON-запросы отправляйте с Content-Type: application/json.

POST /projects принимает {"name":"Учебный проект","zip_base64":"..."} или {"name":"Repair Desk","repository_url":"https://github.com/TBagirov/training"}. Для ссылки серверу требуется доступ к codeload.github.com. Для ZIP интернет не нужен. Этот вариант предназначен для учебного проекта и его собственных безопасных вариаций.
GET /projects и GET /projects/{id} возвращают список или карточку. PUT обновляет name. DELETE удаляет проект и связанные активные определения сценариев, история завершённых запусков сохраняется.
GET /nodes отдаёт каталог типов и default_graph. POST /workflows/validate принимает {"graph":...}. POST /workflows принимает {"name":"Проверка","project_id":"...","graph":...}. GET, PUT, DELETE /workflows/{id} работают с сохранённым сценарием. GET /workflows/{id}/versions возвращает версии.
POST /workflows/{id}/runs с пустым JSON создаёт фоновый запуск и возвращает run_id. GET /runs перечисляет запуски, GET /runs/{id} возвращает состояние и ошибку. GET /runs/{id}/events отдаёт историю в JSON. Укажите Accept: text/event-stream для SSE. Клиент может возобновить чтение с Last-Event-ID и закрыть EventSource при завершении запуска.
PUT /workflows/{id}/schedule принимает {"minutes":15} или {"cron":"0 9 * * 1-5","timezone":"UTC"}. Для часовых поясов IANA на Windows установите tzdata. Узел schedule_trigger должен присутствовать в графе. Пустой объект отключает расписание. Планировщик работает пока запущен сервер.
GET /runs/{id}/report — данные отчёта и AI. GET /runs/{id}/submission.json — экспорт для организаторов. GET /runs/{id}/report.html — читаемая версия. GET /findings — результаты всех запусков, в которых был сформирован отчёт. GET /settings — текущая модель и канал.
GET /inbox показывает полученные сообщения тестового webhook. По умолчанию notification делает реальный HTTP POST на локальный приёмник. Для доставки во внешнюю систему оператор указывает GARDEN_WEBHOOK до запуска сервера. На сервере доступны GARDEN_PORT, GARDEN_DATA, AI_BASE_URL, AI_MODEL. Для совместимого провайдера задайте AI_PROVIDER=openai-compatible, AI_MODEL, AI_BASE_URL и при необходимости AI_API_KEY. Сетевые адреса для модели и уведомлений устанавливает оператор процесса.

Режимы запуска

start_backend.cmd использует встроенный HTTP-сервер Python. Для FastAPI на машине с установленными зависимостями запустите python -m uvicorn fastapi_app:app --host 127.0.0.1 --port 8765 --workers 1. Документация FastAPI доступна на /docs. Выбирайте один сервер для каждого каталога data. Рабочий профиль использует SQLite и один фоновый Python-исполнитель. PostgreSQL, отдельные Celery-воркеры и Redis в эту локальную поставку не включены.

Проверки

python -m unittest -v test_backend
python evaluate.py ПУТЬ_К_training-project ПУТЬ_К_ground-truth/training-findings.json
При запущенном backend команда python check_http.py ПУТЬ_К_training-project проверяет на открытом наборе ZIP, публикацию событий, 15 результатов, HTML и фактическую доставку в локальный webhook. Сама схема этого теста не вызывает LLM. Демо run_demo.cmd отдельно проверяет путь с настоящим AI на одной зависимости.
