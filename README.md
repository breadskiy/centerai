# CenTRap · Security Workbench

Локальное рабочее пространство для статического анализа учебных Kotlin/Spring Boot проектов. Соберите граф из источника, анализаторов и условий, запустите проверку и откройте отчёт с привязкой к файлам и строкам.

## Запуск на Windows

В ветке `main` дважды щёлкните **Start-CenterAI.bat**. Нужны Python 3.12 или 3.13, Node.js 22.12+ или 24 и npm. Для первой установки нужен интернет.

Файл подготовит Python-окружение, соберёт интерфейс и откроет [CenTRap](http://127.0.0.1:8000). Если доступна Ollama с моделью `qwen3:4b`, скрипт подключит её. Веса можно установить командой `ollama pull qwen3:4b`. Когда скрипт сам запускает Ollama, он включает поддержку встроенной графики через `OLLAMA_IGPU_ENABLE` с учётом значения из окружения. Для запуска без готовой Ollama используется локальная модель Qwen на CPU. Она и её сервер занимают около 1,2 ГБ в `.qa/model`. Переменные `AI_PROVIDER`, `AI_BASE_URL`, `AI_MODEL` или `AI_API_KEY` задают собственную конфигурацию провайдера.

Оставьте окно запуска открытым. Для остановки нажмите Ctrl+C. База и ключ шифрования находятся в `data/`. Для резервной копии остановите сервер и сохраните каталог целиком. Ключ нужен для чтения снимков и настроек Telegram. Журналы запуска находятся в `.qa/startup`. [Документация API](http://127.0.0.1:8000/docs)

Чтобы запустить встроенную модель через Vulkan, передайте `-Vulkan` батнику. При сбое запуска через Vulkan CenTRap переключится на CPU. Если настроен отдельный провайдер, CenTRap продолжит использовать его. С `AI_PROVIDER=disabled` можно запускать обычные проверки и отправлять отчёты, а генератор AI сообщит, что модель недоступна.

## Привязка GitHub

В настройках GitHub создай OAuth App. Для локального запуска укажи адрес сайта `http://127.0.0.1:8000` и callback `http://127.0.0.1:8000/api/v1/auth/github/callback`. Открывай CenTRap на том же адресе, что указан в callback. Для запуска на другом порту передай `-Port` батнику и укажи соответствующий адрес в OAuth App. [Документация GitHub OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)

При первом запуске батник попросит Client ID и Client Secret. Пустой Client ID пропускает настройку. Секрет защищается Windows DPAPI и сохраняется в `%LOCALAPPDATA%\CenterAI\github-oauth-8000.clixml` для текущего пользователя Windows и порта. Для замены ключей останови сервер и запусти `Start-CenterAI.bat -ConfigureGitHub`. Флаг `-SkipGitHub` пропускает OAuth для одного запуска. Для развёртывания можно передать `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` и `GITHUB_OAUTH_CALLBACK_URL` через окружение. Docker Compose читает эти переменные из локального `.env`.

- **Зарегистрироваться через GitHub** создаёт аккаунт CenTRap с основным подтверждённым email из GitHub.
- **Войти через GitHub** открывает уже зарегистрированный или привязанный аккаунт вместе с его историей.
- Для существующей учётной записи с паролем используй **Личный кабинет → GitHub → Привязать GitHub**. Для отвязки аккаунта требуется другой способ входа.

После входа или привязки GitHub открой **Мои репозитории** и включи **Автопроверку** у публичного Kotlin/Gradle-репозитория, где ты владелец или приглашённый соавтор. После принятия приглашения нажми **Обновить**, чтобы заново запросить список. Если доступ ещё не сохранён или отозван, нажми **Подтвердить доступ GitHub** прямо на этой странице. Токен для запроса списка хранится на сервере в зашифрованном виде и удаляется при отвязке.

В столбце **Сценарий** нажми **Настроить сценарий**, чтобы открыть визуальный редактор выбранного репозитория. Настрой блоки и нажми **Сохранить**. CenTRap хранит граф отдельно для каждого репозитория, и включённая автопроверка повторно проверит текущий коммит с новым графом. Если в графе есть триггер расписания, для автопроверки он запускается по коммиту.

CenTRap ставит первую проверку в очередь, затем отслеживает актуальную основную ветку и для нового SHA скачивает архив именно этого коммита. Для одного репозитория опрос идёт примерно раз в две с половиной минуты. Интервал растёт с числом отслеживаемых репозиториев, чтобы учитывать лимит GitHub. В списке видны дата и SHA последнего обнаруженного коммита, число находок по его завершённой проверке, статус и ссылка на запуск. Автопроверка работает, пока запущен сервер. Для объяснений модели добавь узел **AI-анализ** в граф.

## Первая проверка

- При открытии CenTRap нажмите **Создать аккаунт**. Укажите почту и пароль от 12 символов. Можно использовать фразу из несвязанных слов. Простые повторы, последовательности и распространённые шаблоны отклоняются. Проверяется формат адреса. Письмо подтверждения не отправляется.
- **Продолжить как гость** открывает ручные проверки. Выход из кабинета завершает гостевую сессию и удаляет её данные. Если закрыть приложение или оставить вкладку свёрнутой, сессия истекает через 30 минут после последнего сигнала от активной вкладки. Выполняющийся анализ отменяется на ближайшем этапе, затем обработчик удаляет его данные.
- Откройте **Личный кабинет** внизу бокового меню, чтобы сохранить никнейм и имя пользователя Telegram. Зарегистрированный пользователь после повторного входа видит свои исходники, сценарии и историю.

При обновлении старой базы записи сохраняются без владельца. Чтобы вернуть их в свой кабинет, зарегистрируйте нужный аккаунт и выполните из корня проекта `.venv\Scripts\python -m backend.claim_legacy email@example.com`. Команда передаёт этому аккаунту все записи из старого общего пространства.

[Пошаговый гайд для ручного тестирования с описанием кнопок и ожидаемых результатов](docs/manual-testing.md)

1. Откройте **Сессии → Новая сессия**. Введите название, выберите GitHub и оставьте предложенную ссылку на Repair Desk. Для собственного учебного проекта можно выбрать ZIP с `build.gradle.kts`.
2. В карточке проекта нажмите **Создать сценарий**. Выберите «Три анализатора и отчёт». Редактор покажет исходники, параллельные ветви поиска секретов, проверки зависимостей и статического анализа Kotlin. Исполнитель обходит эти ветви последовательно.
3. Перемещайте узлы, соединяйте порты мышью или задавайте входящие связи в инспекторе. У IF / ELSE два выхода. Фильтры применяются к результатам на входе выбранной ветви. Изменения сохраняются автоматически.
4. Нажмите **Проверить**, затем **Запустить**. Монитор покажет события, статусы этапов и результат. В разделе «Данные этапов» можно открыть выход узла.
5. Откройте **Результаты сессии** или скачайте JSON и TXT из карточки запуска. Экспорты используют один итоговый набор. В карточке результата есть правило, место, маскированное доказательство и рекомендация.

В мониторе результаты появляются на узлах графа в порядке выполнения. Активный узел подсвечивается. После его завершения на нём появляются уровни критичности и количество обнаружений.

В карточке сессии кнопка **Удалить сессию** удаляет её исходники, сценарии и отчёты. На главной **Очистить историю сессий** удаляет завершённые запуски и их отчёты после подтверждения. Сессии, исходники, сценарии и активные запуски сохраняются. Удаление отдельной сессии доступно из списка и из её карточки. Если у сессии есть активный запуск, сначала завершите или отмените его.

### Расписание и уведомления

Для расписания замените ручной триггер узлом «Расписание», соедините его с источником, укажите пятикомпонентный cron и часовую зону IANA. Включите расписание после соединения графа. Настройте расписание в инспекторе узла. Сервер и обработчик должны работать к моменту запуска. После простоя одна просроченная проверка ставится в очередь, затем рассчитывается следующий срок.

Из своей сессии в документации /docs настройте бота через PUT /api/v1/integrations/telegram и проверьте доставку через POST /api/v1/integrations/telegram/test. Для уведомления по результатам соедините выход узла «Отчёт» с узлом «Telegram».

## Отправка отчётов по почте

Скопируй [`.env.example`](.env.example) в `.env` в корне `D:\Cybergarden`. Укажи SMTP своего отправителя. Батник загружает параметры почты из этого файла, Docker Compose тоже использует его. Локальный `.env` исключён из Git.

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_FROM=ваш-отправитель@gmail.com
SMTP_USER=ваш-отправитель@gmail.com
SMTP_PASSWORD='новый-пароль-приложения-без-пробелов'
PUBLIC_URL=http://127.0.0.1:8000
ALLOWED_HOSTS=localhost,127.0.0.1
```

Для Gmail поля `SMTP_FROM` и `SMTP_USER` содержат один адрес отправителя. Получатель определяется отдельно в приложении. Для Docker Compose также нужен `POSTGRES_PASSWORD`. Если ссылки будут открывать с других устройств, укажи доступный HTTPS-адрес в `PUBLIC_URL` и добавь его хост в `ALLOWED_HOSTS`. Для теста через Mailpit на компьютере укажи `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_SECURITY=local`, тестовый `SMTP_FROM` и оставь `SMTP_USER` и `SMTP_PASSWORD` пустыми.

1. Перезапусти батник из `D:\Cybergarden` и войди в приложение. Открой **Личный кабинет → Отправка по почте**.
2. Нажми **Отправить письмо для подтверждения**. Открой ссылку из письма и нажми **Подтвердить адрес**. Второй ящик можно добавить через **Добавить или изменить адрес → Использовать только для отчётов**. Адрес для входа при этом сохранится.
3. В редакторе сценария добавь узел **Email**, соедини **Отчёт → Email** и выбери получателя. Если оставишь **Почта аккаунта**, отчёт уйдёт на подтверждённый основной адрес. Сохрани и запусти сценарий. Модель для этого пути не нужна.
4. В карточке запуска появится статус **Отчёт по почте**. **Принято почтовым сервером** означает, что SMTP принял письмо. При временной ошибке отправка повторится в фоне. Отчёт сканирования остаётся в CenTRap.

Операции подтверждения, настройки сценария и тестовой отправки также доступны через [документацию API](http://127.0.0.1:8000/docs).

Если модель уже подключена, можно создать сценарий через существующий генератор. Например, «Проверь зависимости и отправь отчёт на почту» использует подтверждённый адрес аккаунта, а «Проверь зависимости и отправь отчёт на reports@example.com» потребует подтверждения конкретного ящика.

## Сценарий по описанию

Открой **Сценарии → Собрать с AI**, выбери сессию и опиши проверку. Например, «Каждый день в 14:30 проверяй код на секреты и сформируй отчёт». Нажми **Сгенерировать сценарий**. CenTRap откроет редактируемый граф. Перед запуском проверь узлы, переходы и получателя. Расписание из описания сохраняется выключенным до явного включения в редакторе.

## Шаблоны и CI

В разделе «Сценарии» опубликуйте сохранённую версию в своей библиотеке. Шаблон можно просмотреть и скопировать в другой проект. Расписание копии включается вручную. Для запуска из CI задайте секреты `CENTERAI_EMAIL` и `CENTERAI_PASSWORD` владельца сценария, затем используйте `python scripts/ci_scan.py --workflow ID --output reports`. Параметр `--archive project.zip` проверяет новый снимок, а `--fail-on HIGH` завершает команду ошибкой при результате уровня HIGH или CRITICAL. Идентификатор сценария находится в URL редактора.

## Docker Compose

В этой конфигурации PostgreSQL хранит данные, Celery Beat ставит задачи обработки в Redis, отдельный Celery worker разбирает очередь. На хост опубликован только порт приложения на loopback. Для первого старта задайте уникальный URL-безопасный пароль в переменной окружения или в файле `.env`. В PowerShell можно сгенерировать значение для текущей сессии.

```powershell
$env:POSTGRES_PASSWORD = [guid]::NewGuid().ToString('N')
docker compose up --build -d
```

Сохраните пароль в локальном `.env` для следующих запусков с тем же томом PostgreSQL. Каталог данных и ключ лежат в постоянном томе `workspace`. Запуск Compose требует установленного Docker с Linux-контейнерами.

| Переменная | Назначение |
| --- | --- |
| `ALLOWED_REPOSITORIES` | Список учебных GitHub-репозиториев в формате owner/repo через запятую. Изначально разрешён TBagirov/training |
| `CENTERAI_DATA` | Каталог локальной базы и ключа. По умолчанию data |
| `DATABASE_URL` | Строка подключения SQLAlchemy. По умолчанию SQLite, в Compose PostgreSQL |
| `CENTERAI_KEY` | Необязательный постоянный ключ Fernet. При отсутствии генерируется файл workspace.key |
| `PUBLIC_URL` | Базовый адрес в Telegram-отчётах. По умолчанию http://localhost:8000 |
| `WORKER_MODE` | local запускает обработчик внутри процесса API. В Compose используется celery |
| `REDIS_URL` | Адрес брокера Celery |

Адрес localhost из сообщения Telegram открывает сервис только на машине, на которой он работает.

## Разработка и тестирование

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
git clone --depth 1 https://github.com/TBagirov/training.git .qa/training
.\.venv\Scripts\python.exe -m pytest -q -s backend/tests
cd frontend
npm ci
npm test
npm run build
npm run e2e
```

При отсутствии Edge на Windows или Chromium на Linux установите браузер командой `npx playwright install chromium`. Путь к существующему Chromium можно передать через `BROWSER_PATH`. Playwright сам поднимает отдельную временную базу и API на порту 8765. Для проверки на конкретной версии набора используйте ревизию из отчёта ниже. Переменная `TRAINING_ROOT` позволяет указать свой путь к нему. При отсутствии набора Pytest явно пропускает только сравнение с эталоном.

Для разработки с горячим обновлением запустите API на 8000 и `npm run dev` из frontend. Vite проксирует запросы к API. Пользовательские данные, архивы, тестовая копия набора и токены исключены из Git.

## Результаты и границы

Готовые примеры выгружены штатными API из одного полного запуска на 22 файлах Repair Desk. [Машиночитаемый JSON](docs/example/submission.json) · [Читаемый отчёт](docs/example/report.txt)

На открытом Repair Desk ревизии `fe1fcbe212669783480666b9b60147c8a8c6eef4` обнаружены 5 SECRET, 5 SCA и 5 SAST. Сопоставление дало TP 15, FP 0, FN 0, precision 1, recall 1 и F1 1. Все шесть отрицательных контрольных примеров прошли. Скрытая вариация организаторов недоступна. Проверка качества и её критерии описаны в архитектурном отчёте.

SCA использует фиксированную учебную базу. Анализаторы покрывают описанные в ТЗ классы в пределах реализованных правил и ограниченного отслеживания локальных значений. Kotlin-проект читается статически. Значения секретов маскируются в интерфейсе, отчётах и результатах узлов.

Узел **AI-анализ** подключает Ollama или совместимый с OpenAI сервер. Выбери модель в инспекторе узла. В истории сохраняются провайдер, модель, версия промпта и результат проверки ответа. При недоступной модели остаются факты анализаторов. [Подключение и проверка AI](docs/manual-testing.md#ai) Для запросов к Ollama CenTRap держит модель в памяти 45 секунд после ответа. Оператор может изменить это время через AI_OLLAMA_KEEP_ALIVE.

Обмен с Telegram проверен на уровне адаптера и обработки ошибки. Доставка в настоящий чат требует настроенного бота. Docker Compose проверяется в GitHub Actions на Linux. Стенд импортирует Repair Desk, выполняет ручной и календарный запуск, проверяет SSE и выгружает оба отчёта. [История проверок](https://github.com/breadskiy/centerai/actions/workflows/acceptance.yml)
